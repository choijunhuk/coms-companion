# 구현 순서와 완료 조건

현재 산출물은 설계 문서 묶음이다. 앱 실행, APK 생성, 실제 단말 검증, 서버 배포는 별도 작업이다. 이후 세션은 저장소의 현재 코드와 검증 기록을 읽고 이어서 진행한다. 단계별로 실제 완료한 것, 테스트로만 확인한 것, 외부 조건 때문에 확인하지 못한 것을 구분해 남긴다.

## P0. 저장소와 설계 기준

프로젝트 목적, 다섯 탭의 화면 흐름, 데이터 소유권, 메시지 실행 경계와 개발 순서를 문서화한다. 공개 저장소에 사용할 예시 데이터는 모두 가상으로 만든다. 앱 서명키·실제 연락처·로그·데이터베이스를 제외할 규칙을 준비한다.

완료 조건은 다른 개발 세션이 문서를 읽고 다음 작업을 판단할 수 있는 것이다. 공개 저장소를 만들거나 동기화했다는 사실을 앱 완성 또는 서비스 배포로 기록하지 않는다.

## P1. 오프라인 앱과 연락 업무

Kotlin·Compose·Room 기준으로 홈·회원·행사·회비·연락 화면을 구현한다. 회원·그룹 관리, 파일 가져오기와 중복 확인, 행사 작성, 회비 부과·수동 납부 확인·정정, 템플릿과 개인별 미리보기, 임원 할 일과 연락 알림을 연결한다.

문자는 문자 앱을 열어 사용자가 직접 전송한다. 카카오톡은 공식 공유 흐름과 일반 공유 대안을 제공한다. 누가 어떤 문구의 대상이었는지 기록하고, 전송 여부를 확인할 수 없으면 그대로 표시한다. 앱 내 알림으로 미처리 업무를 안내할 수 있지만 무인 문자 발송은 넣지 않는다.

완료 조건은 웹 서버 없이 명단 등록부터 안내 준비·외부 앱 실행·결과 기록까지 이어지는 것이다. 앱 재시작 후에도 회원·회비·작업 기록이 유지되어야 한다. 실제 SKT 단말에서 회선 선택, 한글·링크·장문, 취소 후 복귀, 카카오톡 유무를 확인한다. 실발송은 사용자가 선택한 테스트 대상에게 직접 승인해 진행한다.

## P2. 회원용 웹 응답

React·TypeScript·Vite 웹과 Node.js·TypeScript·Fastify·SQLite 단일 서버를 구현한다. 앱에서 행사와 초대를 게시하고, 회원은 앱 설치 없이 참석 응답·일정 투표·안내 확인·입금 확인 요청을 제출한다. 앱은 응답을 받아 미응답자 안내 초안을 만들 수 있어야 한다. 기존 운영 서버 사용과 실제 외부 배포는 권한·환경을 별도로 확인한다.

만료·마감·취소 화면, 응답 수정, 버전 충돌과 동기화 재시도를 완성한다. 공통 링크의 미확인 신청은 운영자가 회원 연결을 검토하고, 게시 전 수동 응답은 최초 게시 때 서버로 전환한다. 게시 후 오프라인 운영자 수정과 회원 응답의 충돌은 검토해 해결한다. 입금 확인 요청은 서버의 주장 기록으로 저장하고 실제 납부 원장 반영은 운영자가 별도로 확인한다. 연락을 준비하는 시점에 현재 응답 조건을 다시 확인한다. 웹 관리자 전체를 추가하지 않는다.

완료 조건은 운영자 앱이 꺼져 있어도 회원이 응답하고, 앱을 다시 열면 누락·중복 없이 반영되는 것이다. 서버 장애 중 작성한 로컬 변경은 복구 후 동기화할 수 있어야 한다.

## P3. 사용성이 확인된 뒤 확장

행사 QR 출석, 운영비 지출과 인수인계, 물품 대여·반납을 작은 단위로 추가한다. 행사 신청과 실제 출석, 회비 수입과 운영비 지출은 각각 구별한다. 여러 운영자 지원은 권한과 충돌 해결을 먼저 설계한다. 로컬 AI는 기본 기능과 독립된 선택 기능으로만 검토한다.

## 검증 기록에 반드시 구분할 것

| 검증 환경 | 확인할 내용 | 이것만으로 확정할 수 없는 내용 |
| --- | --- | --- |
| 단위 테스트·가상 데이터 | 대상 필터, 금액·정정, 토큰, 만료, 충돌, 중복 작업 | 실제 문자·카카오톡 전송 |
| 에뮬레이터·개발 실행 | 화면 이동, 입력, 저장, 외부 앱 호출 경로 | SKT 회선·실기 공유 동작 |
| 실제 안드로이드 기기 | 문자 앱·회선·카카오톡·권한·복귀·재시작 | 수신자가 읽었는지 여부 |
| 별도 기기의 웹 접속 | 응답·수정·마감·취소·동기화·장애 복구 | 실제 배포 전 외부 서비스 가용성 |

회비 충돌, 결과 미확인 작업의 재실행, 응답 마감 직전 동시 수정은 핵심 검증 대상으로 둔다. 발견한 구체적인 위험을 해결한 뒤 다음 기능으로 진행한다. 문서·화면·테스트 결과를 실제 완료 상태보다 앞서 표현하지 않는다.
