# COM’s Companion UI·UX 명세

Android 운영 앱과 회원용 모바일 웹의 화면·문구·상태 기준이다. 회원·행사·회비 정리와 연락 준비를 중심으로, 실제 정보와 다음 행동을 먼저 배치한다. 세부 기술은 아키텍처 문서를 따른다.

## 1. 제품 경험과 첫 실행

Android가 주 사용 환경이다. 첫 화면은 홈이며, 데이터가 없으면 “첫 회원 추가”, “행사 만들기”와 보조 동작 “명단 가져오기”를 제공한다. 시작할 때 클라우드 계정·문자 권한·연락처 전체 접근을 요구하지 않는다. 회원·행사·회비와 연락 준비는 로컬 모드에서 사용할 수 있다.

첫 저장 뒤 “이 기기에 저장됩니다. 설정에서 백업할 수 있어요.”를 한 번 안내한다. 서버 연결이 필요한 회원 응답 링크는 연결 설정이 완료된 경우에만 생성한다. 연결 전 행사 화면에서는 “응답 링크를 사용하려면 연결 설정이 필요해요”와 설정 버튼을 보여 주되, 행사 저장·수동 신청 등록·공지 복사는 계속 가능하다.

기능 사용 시 필요한 권한만 요청하고, 거절되면 수동 입력이나 외부 앱 전달을 제공한다. 권한 동의를 앱 전체 이용 조건으로 만들지 않는다. 예시는 “예시 회원 A” 같은 가상 데이터만 사용하고 실제 전화번호·계좌·납부 정보를 공개 산출물에 넣지 않는다.

## 2. 디자인 토큰

초기 테마는 밝게다. 설정에서 밝게·어둡게·시스템 설정을 선택하며, 시스템 설정은 기기의 다크 모드를 따른다.

| 용도 | 밝은 화면 | 어두운 화면 |
| --- | --- | --- |
| 배경 | `#F6F7F9` | `#10161C` |
| 표면 | `#FFFFFF` | `#18212A` |
| 본문 | `#17212B` | `#ECF2F7` |
| 보조 글자 | `#536171` | `#ADBCCA` |
| 경계선 | `#DCE2E8` | `#344451` |
| 주요 동작 | `#0F766E` | `#67D5C5` |
| 주요 색의 연한 표면 | `#E8F5F2` | `#193B38` |
| 주요 버튼 글자 | `#FFFFFF` | `#10201F` |

8dp 간격 체계, 좌우 여백 20dp(좁은 화면 최소 16dp), 카드 내부 16dp, 섹션 간격 24dp를 사용한다. 카드 모서리는 16dp, 주요 버튼 높이는 52dp, 모든 터치 대상은 최소 48×48dp다. 키보드·시스템 바와 버튼이 겹치지 않게 한다. 약한 경계선과 여백으로 구분하고 장식을 반복하지 않는다.

한국어 시스템 글꼴을 사용한다. 화면 제목 24sp, 섹션 제목 18sp, 본문·입력 16sp, 보조 정보 14sp, 비핵심 라벨 12sp를 기준으로 한다. 금액은 고정폭 숫자·천 단위 쉼표·원 단위를 사용한다. 큰 글자에서도 금액·버튼·상태가 겹치지 않도록 줄바꿈을 허용한다.

정상·대기·실패는 반드시 상태 문구와 아이콘을 함께 제공한다. 색만으로 차이를 전달하지 않는다. 본문 대비와 포커스 표시를 검증하고, 아이콘 버튼에는 읽을 수 있는 접근성 이름을 지정한다. 금융 화면에는 점수·레벨·축하 애니메이션을 넣지 않는다. 완료 피드백은 짧은 문구와 갱신된 기록으로 표현한다.

## 3. 이동 구조와 공통 요소

하단 탭은 **홈 / 회원 / 행사 / 회비 / 연락** 다섯 개로 고정한다. 아이콘 아래에 이름을 항상 표시하고, 선택된 탭만 주요 색으로 강조한다. 탭 전환 시 필터와 스크롤 위치를 유지한다. 설정은 주요 화면 상단 오른쪽 톱니바퀴에서 연다. 탭 안의 상세 화면은 상단 뒤로가기를 사용한다.

대표 행동은 하나로 둔다. 등록은 하단 “저장”, 연락 준비는 “다음” 또는 채널별 명시적 버튼을 사용한다. 미저장 편집을 벗어날 때 “계속 작성 / 변경사항 버리기”를 확인한다. 조회·필터 변경에는 확인창을 띄우지 않는다.

성공 안내는 “저장했어요”처럼 결과를 표시한다. 분류·보관에는 되돌리기를 제공하고 삭제·납부 변경은 대상을 확인한다. 로딩은 구조를 유지한 자리표시자로, 오류는 해당 영역 안에서 표시한다.

## 4. 홈: 오늘 처리할 일

상단은 “COM’s Companion”, 선택된 학기, 설정 버튼이다. “오늘 처리할 일”에 입금 확인 요청·마감 임박·연락 알림·행사 준비 업무를 최대 세 개 표시한다. 항목은 제목, 관련 업무, 대상 수, 행동 버튼으로 구성한다. 나머지는 “전체 보기”로 연다.

각 버튼은 처리 화면으로 이동한다. 예를 들어 “입금 확인 3건”은 해당 회비의 확인 대기 목록으로, “미응답 5명 안내”는 행사와 대상 조건이 채워진 연락 초안으로 이동한다. 홈에서 누르는 것만으로 연락이나 납부 확정이 실행되지 않는다.

“다가오는 행사”에는 가까운 두 개의 날짜·장소·신청 상태를 표시한다. 처리할 일이 없으면 “오늘 확인할 일이 없어요”라고 표시한다. 합계 숫자와 무관한 통계로 화면을 채우지 않는다. 동기화 실패가 판단에 영향을 줄 때 상단에 상태와 재시도를 표시한다.

## 5. 회원

목록 상단은 검색, 활동 상태·학년/기수·소모임 필터, 인원 수, “회원 추가”다. 행에는 이름·기수/소모임·활동 상태를 표시한다. 전화번호는 기본 마스킹하고 상세에서 확인한다. 동명이인은 그룹과 내부 구분 정보로 식별한다. 행은 상세를 열고 체크박스는 다중 작업 대상을 선택한다.

상세는 **기본 정보 / 회비 / 행사 / 연락 기록**이다. 기본 정보에 이름·활동 상태·그룹·연락처를 배치하고 권한이 있을 때 연락처를 표시한다. “전화 앱 열기”는 다이얼러만 연다. “연락 준비”는 이 회원이 선택된 작성 화면으로 이동한다.

회원 양식의 필수값은 이름이다. 전화번호는 문자 연락을 사용할 때 검증하며, 기수·학년·그룹은 선택이다. 활동 상태는 활동·휴면·탈퇴로 제공한다. 같은 번호나 유사한 이름이 있으면 기존 후보를 보여 주고 새 등록 또는 수정 여부를 선택하게 한다. 자동 병합하지 않는다.

명단 가져오기는 열 매핑 → 미리보기 → 정상·오류·중복 행 확인 → 적용 순서다. 오류 행의 원인을 표시하고 기존 회원을 덮어쓰는 항목은 구분한다. 다중 선택 도구에는 그룹 변경·활동 상태 변경·연락 준비를 제공한다. 탈퇴 처리 시 이후 기본 연락 대상에서 제외되는 것을 설명한다.

## 6. 행사

목록은 예정·진행·종료로 구분하고 날짜순으로 표시한다. 카드에는 이름·일시·장소·신청 인원·마감 상태를 배치한다. 생성은 기본 정보 → 신청·응답 설정 → 검토 순서다. 이름을 필수로 받고 일시·장소는 미정으로 남길 수 있다. 참가비·정원·마감·추가 질문·안내사항을 설정하며 시간은 한국 기준이다.

상세는 **개요 / 참여자 / 준비·정산**이다. 상단에 “수정”, 대표 행동 “공지 준비”를 둔다. 참여자는 참석·불참·미정·미응답·확인 대기로 필터링하며, 출석도 여기서 처리한다. 준비·정산에 할 일·참가비·수입·지출을 둔다. 응답 수정에는 변경 주체를 기록한다.

개요에 신청 링크·공지 복사와 날짜 확정 전 “일정 투표 만들기”를 둔다. 투표는 후보 날짜·마감·복수 선택으로 작게 구성하고 결과 확인 후 운영자가 일시를 확정한다. 정원·마감 변경은 영향을 설명한다. 취소 시 “취소됨”과 후속 안내 준비를 제공한다. 출석 확인은 되돌릴 수 있으며 QR은 선택 기능이다.

## 7. 회비

기본 화면은 회비 항목 목록이다. “2026년 2학기 회비”, “예시 행사 참가비”처럼 항목별로 청구 합계·확인된 납부·남은 금액을 구분한다. 숫자 아래 정의가 필요하면 짧게 제공한다. 미납 총액이 동아리의 전체 현금 잔액처럼 보이지 않게 한다.

상세 상단에는 항목명, 기한, 기준 금액을 두고, 아래 회원별 청구·확인된 납부·남은 금액을 표시한다. 상태 필터는 전체·입금 확인 대기·미납·일부 납부·완납·면제·환불을 제공한다. “미납자 연락 준비”는 현재 조건을 적용한 명단 미리보기로 이동한다.

“납부 기록”은 회원·금액·날짜·메모를 확인해 저장한다. 웹의 “입금했어요”는 서버가 보관하는 **입금 확인 요청**이며 완납이 아니다. 회장 소유 단말의 로컬 원장에서 대상·금액을 검토하고 “입금 확인”해야 납부가 확정된다. 정정·면제·환불에는 이전 기록과 사유를 남긴다. 잔액을 직접 덮어쓰지 않는다.

## 8. 연락: 초안에서 채널 전달까지

연락 화면은 **준비 중 / 연락 알림 / 기록 / 템플릿**이다. “연락 만들기”로 시작하며 다음 순서를 고정한다.

1. **목적:** 회비 안내, 행사 안내, 미응답 안내, 직접 작성 중 선택한다. 관련 행사나 회비 항목을 지정하고 내부 관리 제목을 입력한다.
2. **대상:** 그룹·신청 상태·납부 상태 필터로 대상을 고른다. 선택 수, 제외된 인원과 이유, 개별 제외를 보여 준다. 대상 조건과 현재 조회 시점을 함께 보관한다.
3. **문구:** 템플릿을 선택하고 행사명·이름·금액·일시·링크 같은 항목을 치환한다. 누락된 필수 정보는 해당 위치에서 수정하게 한다. AI 없이 문구가 완성되어야 한다.
4. **미리보기:** 개인별 최종 문구를 이전·다음으로 확인한다. 모든 수신자에 대해 누락 정보와 문자 분할 가능성을 검사한다. “1/12 예시 회원 A”처럼 확인 중인 대상을 명확히 표시한다.
5. **채널 전달:** 문자 앱, 카카오톡 공유, 일반 공유·복사를 선택한다. 해당 채널의 수신 대상과 내용이 어떻게 전달되는지 최종 확인한 뒤 채널에 맞는 버튼을 누른다.

최종 버튼은 **“문자 앱에서 보내기” / “카카오톡으로 공유” / “내용 복사”**다. 문자는 작성 화면으로 전달한 뒤 그 앱에서 실제 전송하고, 카카오는 카카오톡에서 대상을 선택함을 설명한다. 개인 문자는 한 사람씩 처리하며 진행 위치를 보존한다. 번호들을 그룹 대화로 묶어 노출하지 않는다.

단톡방 공지는 공통 문구 전용 미리보기를 사용한다. 개인 이름·미납액·전화번호·개인 응답 토큰이 포함되면 단톡방용 문구로 먼저 수정하게 한다. 공통 행사 링크는 특정 회원의 권한으로 응답할 수 있는 링크와 구분한다. 카카오톡의 실제 대상 선택을 앱이 대신 완료했다고 표시하지 않는다.

발송 직전에 납부·응답 상태가 바뀌면 “2명이 안내 대상에서 제외됐어요”와 갱신된 목록을 보여 준다. 새 수신자가 늘거나 문구가 바뀌면 갱신된 미리보기를 확인하게 한다. 사용자가 준비한 범위를 조용히 확대하지 않는다.

## 9. 연락 상태와 예약 문구

| 화면 상태 | 의미와 표시 기준 |
| --- | --- |
| 초안 | 저장된 문구와 대상. 전송하지 않음 |
| 확인 필요 | 누락 정보·변경된 대상·결과 불명확 등 처리 필요 |
| 앱 전달됨 | 문자 또는 카카오톡 선택 화면을 열었음 |
| 결과 미확인 | 외부 앱에서 실제 전송했는지 확인할 근거가 없음 |
| 사용자 발송 확인 | 운영자가 보냈다고 기록함. 사업자 확인과 구분 |
| 전송 결과 확인 | 공식 API·웹훅 등에서 확인한 결과와 채널을 표시 |
| 실패 | 확인된 실패 사유가 존재함 |
| 회원 응답 완료 | 자체 응답 페이지에서 명시적으로 제출함 |

`ACTION_SENDTO`나 공유 화면에서 돌아오면 앱 전달됨을 유지하고 “발송했다고 표시 / 나중에 / 다음 대상”을 제공한다. 복귀를 전송·수신·읽음으로 처리하지 않는다. 미확인 결과를 자동 재전송하지 않으며, 공유 웹훅도 회원별 읽음·참석 확인으로 사용하지 않는다.

예약의 이름은 “연락 알림”이다. 시간·대상·문구를 저장하고 준비된 초안을 여는 알림을 제공한다. 알림이 타인에게 연락을 보내지 않으며 “예약 발송 완료”라고 표시하지 않는다. 이후 유료 자동 발송은 별도 채널로 구분한다.

## 10. 설정과 비용

설정 순서는 **동아리 정보 / 학기 / 서식·템플릿 / 문자·카카오 연결 / 온라인 응답 연결 / 데이터 가져오기·백업·복구 / 앱 잠금 / 알림 / 비용·선택 기능 / 운영 도구 / 앱 정보**다. 운영 도구에서 물품 대여·추가 도구를 연다. 백업 시점을 표시하고 복구의 변경 범위를 확인한다. 연결 해제와 데이터 삭제는 구분한다.

연결은 사용 가능한 기능과 준비가 필요한 기능을 구분한다. API 키가 없는데 성공 상태를 표시하지 않는다. 필요한 기능을 선택할 때 계정·권한을 설정하고 원래 작업으로 돌아간다.

비용 패널의 기본값은 **유료 LLM 꺼짐 / 문자 발송 API 꺼짐 / 알림톡 꺼짐**이다. 로컬 템플릿에는 “AI 호출 없음”, 단말 문자에는 “통신사 요금제 적용”, 카카오톡 공유에는 “제공 쿼터 내 이용”을 표시한다. 확인하지 않은 요금제 잔여량이나 무제한 비용을 추정하지 않는다. 선택형 AI를 활성화할 때만 제공자·비용 한도·사용 기록을 노출하고 핵심 기능은 계속 독립적으로 작동한다.

## 11. 회원용 모바일 웹

P2 웹은 **신청·참석 응답(RSVP), 안내 확인, 일정 투표, 입금 확인 요청**으로 고정한다. 설치 배너 없이 행사 상세 → 입력 → 최종 확인 → 완료로 이어진다. 동아리명·행사명·일시·장소·참가비·마감·안내사항을 먼저 보여 준다. 최대 읽기 폭은 약 640px이며 앱의 색·용어를 공유한다.

단톡방 공통 링크는 기본적으로 로그인 없이 자기신고 응답을 받는다. 제출은 “미확인”으로 저장하고, 운영자가 행사 참여자의 “확인 대기”에서 검토해 기존 회원과 연결한다. 이름·전화번호 일치만으로 기존 응답·납부를 덮어쓰거나 개인 정보를 보여 주지 않는다. 완료 화면에도 “운영자 확인 대기”를 표시한다. 수정은 제출 시 받은 수정용 토큰으로 해당 응답에만 허용한다.

개인 링크는 행사·회원·동작·유효기간이 제한된 토큰의 소유로 해당 제출을 인증한다. 전체 계정 권한을 주지 않는다. GET·미리보기 접근은 상태를 바꾸지 않는다. “참석으로 제출”, “안내 확인”, “입금 확인 요청”을 명시적으로 제출하고 결과를 확인한다. 중복 탭을 막고 통신 실패 시 내용을 보존한다.

일정 투표는 가능한 후보를 선택하고 “투표 제출”로 확인한다. 완료 화면에 선택·시각·수정 기한을 표시하며 허용 기간에는 “투표 수정”을 제공한다. 공통 링크 투표도 미확인 응답이다. RSVP·안내 확인·입금 요청 역시 제출 결과를 각각 표시한다. 입금 요청 완료를 납부 완료로 표시하지 않는다.

마감·정원 초과·행사 취소·링크 만료·결과 미확인은 개별 상태로 안내한다. 마지막 정원이 먼저 찼으면 성공으로 처리하지 않는다. 지원하지 않는 대기 신청을 약속하지 않는다. 수정할 권한이나 기한이 없으면 변경 버튼 대신 이유를 표시한다.

## 12. 오프라인·알림·큰 화면

공개 전 수동 RSVP는 로컬에서 관리한다. 최초 게시 검토 화면에 “수동 응답 N건 포함”을 표시하고 함께 업로드한다. 게시 이후 응답 원본은 서버다. 운영자의 오프라인 응답 수정은 “반영 대기 변경 제안”으로 표시하고 서버가 수락해야 확정한다. 버전 충돌은 최신 응답과 제안을 비교해 검토한다.

회원·회비의 소유자 로컬 원장과 온라인 응답 원본을 구분한다. 오래된 응답을 사용하면 마지막 동기화와 최신 확인 필요를 표시한다. 오프라인에서도 초안 편집·복사·로컬 조회를 유지한다. 실패한 제출은 보존하고 네트워크 복구 시 메시지를 자동 재발송하지 않는다.

알림은 오늘 처리할 일과 사용자가 예약한 연락 시간을 중심으로 제공한다. 잠금 화면에는 개인 미납액·전화번호 같은 내용을 기본 노출하지 않는다. 알림 권한이 없어도 홈의 처리 대기 목록에서 같은 업무를 찾을 수 있다.

PC 웹은 이후 회원 표 편집·명단 가져오기·회비 대조용으로 작게 확장한다. 선택·필터·저장과 권한은 모바일과 일치시킨다. 모든 화면을 빈 상태·처리 중·실패·권한 부족·좁은 화면·큰 글자 상태에서도 읽고 조작할 수 있게 한다.
